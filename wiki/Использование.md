# Использование

Anchor полезен, когда агенту нужен локальный рабочий контур без лишней болтовни.

## Общий принцип

- сначала `health`
- потом `config get`, если есть сомнения в настройках
- затем `add` / `update` / `delete`
- для навигации `list`
- для одной сущности `get`
- для поиска `search`
- держи `project` явным
- используй `correlation_id`, если нужен след цепочки
- заполняй `metatags` по схеме, а не произвольно

## Notes

```bash
./.venv/bin/anchor notes add --title "RAG plan" --body "Use SQLite FTS + vector + rerank" --project repo-a
./.venv/bin/anchor notes list --project repo-a --limit 5
./.venv/bin/anchor notes search --query "RAG plan" --project repo-a
```

## Tasks

```bash
./.venv/bin/anchor tasks add --title "Ship retrieval" --project repo-a
./.venv/bin/anchor tasks list --project repo-a --limit 10
./.venv/bin/anchor tasks search --query "retrieval" --project repo-a
```

## History

```bash
./.venv/bin/anchor history append --entry-type deploy --payload "Deploy completed" --project repo-a
./.venv/bin/anchor history search --query "deploy" --project repo-a
```

## Files

```bash
./.venv/bin/anchor files index --root /path/to/repo --project repo-a
./.venv/bin/anchor files list --project repo-a --limit 20
./.venv/bin/anchor files search --query "rate limiter" --project repo-a
```

## Пагинация

- `list` команды возвращают `next_cursor`
- `files list` использует cursor по UUIDv7 `document_id`
- `search` использует opaque cursor по `score + id`
- для больших проектов не пытайся выгрузить всё одной страницей
- cursor pagination нужна и для CLI, и для MCP

## Практический совет

Если агенту нужен ответ, ему почти всегда хватает компактного режима.

Полный режим включай только когда реально нужен полный объект, а не краткая навигационная карточка.

Если нужен готовый шаблон подключения агента к Anchor, см. [Скилл для агента](./Скилл.md).
