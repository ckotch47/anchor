# Метаданные и связи

Anchor использует два простых механизма, чтобы знания оставались структурированными, но не раздували схему.

## Correlation ID

- `correlation_id` связывает действия в одну цепочку
- его удобно проставлять для note/task/history/file workflow
- это не заменяет `id`, а дополняет его

## Typed metadata schema

- `metatags` остаётся JSON-полем
- но структура валидируется по схеме из конфига
- схема задаётся отдельно для `notes`, `tasks`, `history`, `files`
- это помогает не тащить мусорный JSON в прод

## Typed links

- `document_links` строит лёгкий граф поверх SQLite
- связь должна иметь `relation_type`
- типы связей лучше держать белым списком

## Когда это полезно

- когда агенту нужно связать заметку, задачу и историю
- когда поиск должен работать по смысловым связям, а не только по тексту
- когда хочется строить knowledge graph без отдельной базы графов
