# Поиск

Anchor использует гибридный поиск.

## Из чего состоит поиск

1. lexical candidates из FTS
2. vector candidates из SQLite vector search
3. rerank через provider contract
4. dedup
5. trim до token budget
6. compact response

## Как искать

- по notes, tasks, history и files
- по одному project или по заданной области
- cross-project search включается только явно через `--projects`
- с `--view compact` по умолчанию
- с `--view full`, когда нужен полный объект

## Пагинация

- `list` возвращают `next_cursor`
- `files list` курсорует по UUIDv7 `document_id`
- `search` использует opaque cursor из `score + entity_type + entity_id`

## Что важно для токенов

- compact hits должны быть дефолтом
- бюджет триммится до возврата ответа
- если vector-слой недоступен, search должен деградировать, а не падать
- IVF-индекс — это следующий performance upgrade после измеримого роста corpus, а не базовый путь

## Файлы

Для файлов поиск работает по тому же принципу, но source of truth — файловая система, а не таблица памяти.
