# Операции

## Health

`anchor health` проверяет готовность и может запускать плановое обслуживание.

## Очистка

`anchor db compact` отвечает за:

- soft-delete cleanup
- FTS rebuild
- WAL truncation
- vacuum, если он включён

## Конкурентность

- записи сериализуются локальным lock'ом
- несколько агентов должны ждать, а не ломать данные

## Обслуживание

- WAL не должен расти бесконечно
- FTS надо rebuild'ить при фрагментации
- tombstones надо вакуумить по расписанию
- vector fallback для больших corpora должен быть явным

## Практическое правило

Если агенту нужен стабильный ответ, сначала выбирай compact read path, а не попытку вытащить всё списком.
