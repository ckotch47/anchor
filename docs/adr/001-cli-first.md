# ADR-001: CLI-first architecture

- Status: accepted
- Context: инструмент нужен локально для агентов, без веб-API и без обязательного MCP-слоя. Главная цель - дать агентам стабильный машинный контракт, который уменьшает token burn и быстро возвращает нужный срез данных вместо полного контекста.
- Decision: основным интерфейсом сделать CLI. Команды должны быть неинтерактивными по умолчанию и возвращать structured output.
- Alternatives:
  - Local server + CLI wrapper
  - Web API
  - GUI-first
- Trade-offs:
  - Плюсы: проще установка, меньше инфраструктуры, легче локальная эксплуатация, понятный путь для одного пользователя.
  - Минусы: агентский контракт нужно спроектировать аккуратно, иначе CLI быстро станет неудобным.
- Consequences:
  - Каждая команда должна иметь стабильный args contract, JSON output и понятные exit codes.
  - Человеческий TTY-режим является надстройкой, а не основным режимом.
  - Позднее можно добавить серверный слой поверх того же core, но не наоборот.
