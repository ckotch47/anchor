# Agent Usage

Этот документ фиксирует, как агент должен работать с CLI-инструментом.

## Основной принцип

Агент не должен тащить полный контекст, если достаточно компактного retrieval-ответа.

## Порядок работы

1. Сначала искать уже существующие данные через `search` или `recall`.
2. Если данных не хватает, делать `capture` или `append`.
3. Для задач использовать `tasks` как источник текущего состояния.
4. Для заметок и истории использовать их как долговременные рабочие следы.
5. После изменения сохранять минимально достаточный результат, а не полный дамп.
6. Помнить, что `memory` - это retrieval surface поверх notes/tasks/history, а не отдельная source-of-truth таблица.

## Контракт для агента

- stdout должен быть структурированным.
- ошибки должны быть машинно различимыми.
- команды должны работать без интерактивных подтверждений.
- приоритет у коротких ответов и компактных полей.
- later MCP over stdio can reuse the same use-cases as a thin transport layer for agent integrations.

## Что агенту не следует делать

- не запрашивать полный объект, если хватает краткого среза;
- не дублировать один и тот же контекст в нескольких сущностях;
- не использовать CLI как чат-бота;
- не считать rerank обязательным, если retrieval уже дал достаточный результат.
